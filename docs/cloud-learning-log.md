# クラウド教科書・統合記録

## 2026-09-20 課金・サービスモデル・SAN・ストレージ・オーケストレーション
- 中心知識：変動に合う課金、独自コードと管理責任、SANの識別と冗長経路、DBに合う保存方式、コンテナ集団の運用。
- 前提：利用時間と単価、セッションとCookie、OSとランタイム、ブロックI/O、HBA・SFP・FC、コンテナイメージ。
- 周辺：利用確約、専用ホスト、計測、アフィニティ、XaaS、ゾーニング、LUN公開、マルチパス、RAID、IOPS・遅延、Pod・Deployment・HPA。
- 比較：料金と計測と専有は別の軸。IaaS/PaaS/SaaSは管理範囲。保存APIと一時性は別の軸。レジストリ・ポートマッピング・単独実行とオーケストレーションの役割を整理。
- 誤解：Cookieだけで状態が共有される／従量課金は常に最安／WWPNのA0・B0が共通の規則／番号を空きへ変えるだけで接続できる／リンク速度とRAIDだけでIOPSが分かる／ブロックなら必ず最速／Kubernetes導入だけで自動増減する、を防ぐ。
- 実務：安定分と変動分の総費用比較、PaaSの制約、実WWPNと割り当ての照合、片系障害試験、負荷条件を定めた性能測定、望ましい状態と観測のループ。
- 新章：pricing（レベル2）、san（レベル3）、orchestration（レベル6）。20トピックへ拡張し、既存URLを維持。
- 本文改善：cloudにPaaSの選択と責任、storageにDBのI/Oと一時性、scalingにセッション管理を統合。
- 関連：databaseから保存方式、containers・registry・automationからオーケストレーションへ接続。
- 図解：課金の分岐、二重ファブリック、オーケストレーションの制御ループを追加し、計13図。
- 公式根拠：AWSの料金・DB保存・セッション、MicrosoftのPaaS、CiscoのWWPN・FC速度、NetAppの冗長構成、IBMのRAID、Kubernetesの制御・スケール。
- 公開：ユーザーがこれまでの変更を含む本番反映を明示的に承認。確認後に既存PRをmainへマージし、GitHub Pagesを検証する。

## 2026-09-20 管理されたデータベースの責任共有
- 入力テーマ：プロバイダー管理DBで利用者が負う責任。問題文・選択肢は転載しない。
- 中心知識：事業者が実行する基盤保守と、利用者が行うデータ保護・公開された構成の選択を区別する。
- 前提：DBエンジン、行と列、暗号化、クラスタ、主系・待機系・読み取り用複製。
- 周辺：更新時期と自動更新設定、互換性確認、容量・可用性、鍵管理、バックアップ。
- 比較：保存時／通信時／行・項目単位の暗号化、RLSによるアクセス制御、物理基盤と利用構成。
- 誤解：マネージドなら利用者の仕事はない／暗号化とRLSは同じ／全製品でクラスタ構成を選べる／複製はバックアップになる、を修正。
- 実務：誰が実行し、誰が設定し、何を調整するかを書き分ける。製品に公開された設定範囲で判断する。
- 統合先・章整理：既存databaseに5つの深掘り節と責任分担図を追加。17章のまま、cloud・iam・scaling・recoveryにつなげる。
- 本文改善：スポーツ大会の記録係を比喩にし、更新の実行と時期の選択、内部クラスタ運用と利用者の構成選択を明確に区別。
- 根拠：AWS RDSの責任共有・メンテナンス・Multi-AZ、PostgreSQLの暗号化・RLS公式資料。

## 2026-09-20 図解の拡充と、最初の問題からの統合
- 入力テーマ：コンテナイメージの保存・共有・複数環境への再利用。問題文・選択肢は転載しない。
- 中心知識：イメージレジストリ。保存する配布物と、実行状態、業務データを区別する。
- 前提：アプリ、プロセス、実行環境、OSカーネル、VM、イメージとコンテナ。
- 周辺：Dockerfile、ビルド、push/pull、タグとダイジェスト、環境設定、権限、版の更新。
- 比較：永続ボリュームはデータの保存、オーケストレーションは配置と実行管理、スタンドアローンは動作形態。
- 誤解：イメージをpushすればアプリが起動する／業務データも保存される／同じイメージならどんなCPU・OSでも動く、などを明確化。
- 実務：検証済みの配布物を本番でも使用、登録・取得権限の分離、秘密情報を含めない、データを外部へ永続化。
- 統合先：既存のcontainersを基礎から大幅に深掘り。registryを直後へ追加し、automation・storage・iam・recoveryと関連付ける。
- 章整理：既存8レベルを維持。containers → registry → automationの順とし、既存URLを維持。
- 図解：学習ピラミッド、VM階層、保存方式分岐、DNS順序、責任比較、負荷分散構成、復旧時間軸、イメージとコンテナの関係、レジストリとデータ保存の経路を追加。既存の流れも矢印付きに改善。
